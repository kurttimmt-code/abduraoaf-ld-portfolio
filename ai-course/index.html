01 / THE DESIGN CHALLENGE

Translate AI awareness into safer workplace decisions.

The capability problem

Busy professionals can be curious about AI without knowing where it helps, which information may be shared, or how to check a convincing answer. An awareness-only course is unlikely to close this gap.

  • Unsuitable tasks and inappropriate inputs
  • Vague prompting and weak quality specifications
  • Unverified outputs and unclear accountability

The proposed learning response

Teach a usable workflow: identify the work, check approval, build a purposeful prompt, verify the output, and secure human sign-off where required.

  • Short, progressive lessons for time-constrained learners
  • Application practice and consequence-based feedback
  • A printable job aid for on-the-job transfer

Design assumption: a generic, international professional-services audience. Role-specific policies, needs data and capability baselines would need validation in a real deployment.

02 / WHO THIS IS FOR

Designed around the realities of professional work.

Audience

Busy knowledge workers

Employees who draft communications, review documents, develop ideas and work with information.

Starting point

Mixed levels of AI confidence

No prior generative AI experience required; each concept is introduced before it is applied.

Design constraint

Trust and professional accountability

Use generic examples, fictional scenarios, approved-tool reminders and visible human review steps.

Performance goal: After learning, professionals should be able to select an appropriate AI-assisted task, protect inputs, shape useful prompts, verify outputs and retain accountability for the decision.

05 / DESIGN METHODS

Each design choice has a learning purpose.

ADDIE / ITERATION

Start with performance, not tools

Define capability needs, align practical activities to observable outcomes, prototype the learner experience, test usability and refine.

SCENARIO-BASED LEARNING

Practice consequential decisions

Fictional client update: protect input → verify draft → obtain approval. Each choice produces targeted feedback and a retry opportunity.

COGNITIVE LOAD + ACCESSIBILITY

Make essentials easier to use

Chunk information, pair concise visuals with explanations, and support keyboard-friendly interactions. Add verified captions and a matching transcript, then audit accessibility against WCAG 2.2 AA before formal deployment.

DESIGN DECISIONS · FROM PRINCIPLE TO PRODUCT

What was built and why it takes this form.

These design choices connect learning objectives to the course's working interactions. An organisational pilot could extend the evaluation to real-world learning transfer.

DECISION 01 · SAFE TASK SELECTION

Teach judgement before prompt writing

Implemented: A task-classification activity asks learners to consider suitability, approval and risk before selecting an AI-assisted workflow.

Design reason: A technically good prompt is not useful when the underlying task should not be delegated to AI. The sequence makes the safety decision a prerequisite, not a footnote.

Experience Lesson 02 →

DECISION 02 · GUIDED PRACTICE

Turn a vague request into a structured prompt

Implemented: An interactive prompt builder scaffolds a goal, relevant context, constraints and expected format.

Design reason: Showing a template is less powerful than having learners assemble and improve one. Practice makes the components easier to retrieve during work.

Experience Lesson 03 →

DECISION 03 · CONSEQUENTIAL SCENARIOS

Rehearse privacy, verification and sign-off together

Implemented: A fictional client-communication scenario links decisions about input safety, claim verification and human accountability.

Design reason: Workplace performance involves connected judgements. Immediate, explanatory feedback shows why a choice is safer, not merely whether it is correct.

Experience Lesson 05 →

DECISION 04 · EVIDENCE AND ETHICS

Require applied mastery without collecting learner data

Implemented: Ten applied assessment questions with an 80% pass threshold, corrective feedback and progress held on the learner's own device.

Design reason: Completion alone is not evidence of capability. Local progress avoids unnecessary server collection in a demonstration, while the score indicates practice-level mastery, rather than proven workplace impact.
